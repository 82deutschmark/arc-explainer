Connect ARC Prize’s results
to the evidence behind them

The most important gap is the journey from a published model score to an individual task and its original attempts. Current model pages, the task browser and downloadable results expose different coverage. A few key research links also fail.

This report separates reproducible failures from publication decisions and optional product improvements. It is based on the public site and its public data; no private source repository was inspected or changed.

Main findingsHint qualityTask-viewer comparisonFix listScope & corrections

The central request for Matt: please restore public ARC1/2 raw-attempt publication, or link the replacement source. ARC Explainer turns those published results into individual answers, reasoning logs where released, comparisons and statistics. Without the newer downloadable attempts, Mark cannot ingest them or offer the same inspection for newer models—even with a working viewer ready to use them.

The inspected Hugging Face evaluation repositories last changed on June 4, 2026. Newer official model pages publish scores, but this audit found no successor ARC1/2 raw-attempt source in the inspected channels. That establishes a publication/discovery gap, not proof of a permanent shutdown. AP-07 asks for the publication decision and a usable data route.

The examples below show what the earlier releases made possible. Linking community tools helps people find them; continuing to publish the underlying attempts is what lets those tools stay useful.

What deserves attention first

  1. Task hints can contradict their own statistics. An unsolved-in-our-archive ARC2 example displays “6 shapes → 6 shapes” beside “SHAPE COUNT CHANGE.” The same mismatch appears in 16 training examples across 10 tasks. These labels need consistent definitions and must not stand in for an explanation of the rule. AP-20
  2. The default ARC3 task browser fails. Its full model query receives a request-body-size error; a smaller control query succeeds. This is reproduced in the live browser and the public API. AP-01
  3. The ARC1/2 default model selection has no matching task records. All five featured model IDs are absent from the summary feed. ARC2’s default matrix shows N/A throughout; selecting an older covered model restores results. AP-02
  4. Task summaries omit successes already published by ARC Prize. Task 0934a4d8 lists 39 ARC2 summary rows, all failures, but ARC Prize’s HF Opus 4.6 high artifact has two correct attempts. The missing configuration is a coverage problem, not proof that its old rows have incorrect outcomes. AP-03
  5. The raw ARC1/2 publication route needs an explanation. Both official HF repositories still report June 4 as their last update. Newer model pages publish results, but no successor raw-attempt source was found in the inspected official channels. Link the replacement, resume publication, or clearly label unavailable data. AP-07
  6. Historical work is still present but poorly connected. Older blog reports survive, and the o3 data remains in Git history. The modern Results index does not lead back to them; the o3 article’s prompt link is broken and its data link opens an unrelated sample folder. AP-05–08

Task hints need to earn the reader’s trust

Open official task 13e47133 → Details and inspect Training Example #1: the table says 6 shapes → 6 shapes, while the adjacent badge says SHAPE COUNT CHANGE. Example #3 repeats this with 4 → 4. If the page jumps before its model table finishes loading, click Details once more.

Inspect the same task and saved attempts in ARC Explainer. Our mixed archive has 119 scored attempts and no fully correct result for this task in this check. This is an archive statistic, not a claim that the task is globally unsolved.

The public metadata contains the same mismatch in 16 training examples across 10 ARC2 evaluation tasks. Counts by color do change, which may explain the badge; its wording should say that instead of conflicting with the total shown alongside it. These are descriptive grid statistics. They do not establish the puzzle’s transformation rule.

Requested improvement: make the labels agree with the displayed measurements, disclose how shapes/backgrounds are inferred, and clearly distinguish statistics from checked explanations and unverified hypotheses. A helpful task viewer should let the reader trace a claimed rule back to the actual examples and model attempts.

The current training hints in all 120 ARC2 evaluation metadata files contain only sameSize, newColors and shapeCountChange. The generic tooltip mentions rotation/reflection, but this pass did not reproduce a false reflection rule or establish AI authorship. The confirmed finding is the inconsistent label above; the wider concern about explanation quality should be reviewed on its evidence.

What ARC Explainer adds to individual-task examination

The official viewer is useful: it offers playable training/test grids, answer checking, task-source links, structural metadata and a sortable model table. Modern model pages also have per-task result matrices, reasoning comparisons and ARC3 replays. The proposed improvement is to carry that experience through to the actual saved model answer.

Read the published reasoning, then inspect the predicted and expected grids below it. For the same task, Opus 4.5 32k first attempt (#56958) preserves a November 2025 record with a populated reasoning log and two incorrect test outputs. Turn on “Show Mismatches” to examine those failures. Both links select the specific saved attempt; no API key or new model run is needed.

That historical comparison is the point: these are inspectable records of how models approached the same puzzle, not just old leaderboard percentages. The displayed record date may be an import/save date rather than the original run date.

On Analytics, the checked Opus 4.6 max first attempt has 77 correct, 40 incorrect and 3 unattempted ARC2 tasks. Successful runs average about 13 minutes; failures about 23 minutes. That answers a practical question a single benchmark percentage cannot: where did the effort go?

The two-attempt comparison shows 83 fully solved tasks and 119 correct test pairs, explicitly distinguishing those denominators. These workflows make the published records useful for failure analysis.

Fair comparison: ARC Explainer combines official imports with community/local runs. Coverage, prompts and settings can differ. Some response/metadata fields are absent; saved/import dates are not necessarily run dates. Its displayed default confidence values are not a feature to copy without provenance. No claim is made that every record is an official comparable evaluation or that either site is flawless.

Distinct community resources worth reviewing

ARC Explainer is already listed on the official Resources page as “ARC-AGI Puzzle Explorer,” linking to Analytics. The request is to review its individual resources and give visitors useful direct links, rather than treat the whole project as one old analytics page.

  • The ARC Daily: a new news page covering ARC-AGI-3 and ARC-AGI-2, with linked reporting and competition context.
  • Curated synthetic ARC-3 games: a separate catalog for exploring community/research games. These are not the official hidden test set, and no claim is made that playing them predicts competition performance.
  • Official public-game guides, Space Force Mission Control, and the play resources address different learning and exploration needs. Review audience, usability and access requirements individually.
  • The ARC1/2 results archive and exact saved attempts above offer detailed model-answer inspection. Keeping these current depends on access to new raw results.

These are candidates for editorial review, not a demand to list every project or a claim that all other resources are inferior. See AP-16.

Make transformation hints consistent and distinguish statistics from rules

Open affected task

Observed. Training example 1 displays Shape Count: 6 shapes → 6 shapes beside SHAPE COUNT CHANGE. Example 3 repeats this with 4 → 4. Proposed change. Use a total-count-change hint only when the displayed total changes. If the intended signal is changed counts by color, label it explicitly as such. Present these as computed grid statistics, separate from reviewed rule explanations. Define the background and shape-counting assumptions. Only describe a puzzle rule as verified when it has been checked against all provided pairs; label conjectures and link their evidence.

  • Compare the Shape Count row with the adjacent Transform Hints badge.
  • Sum input/output shapeCountsByColor in the linked public metadata and compare with ioComparison.transformHints.

Acceptance checks

  • 13e47133 examples 1 and 3 no longer imply a changed total beside unchanged totals.
  • All 120 ARC-2 evaluation metadata files pass a hint-versus-displayed-statistic consistency check, including the 16 recorded cases.
  • The UI distinguishes descriptive statistics, speculative interpretations and verified explanations; a visitor can inspect the supporting grids.

Per-color counts do change in these examples, so this is a confirmed labeling inconsistency, not proof that the underlying calculation is wrong. Scope, evidence and corrections

HTTP/content checks covered all 72 sitemap URLs, plus discovered internal destinations: 175 distinct requested internal URLs in total. The resource catalogue contained 246 entries. We checked 410 distinct external destinations from resource/core journeys and inspected playability status for 95 video watch URLs. These checks are an availability inventory, not full interaction tests of every destination.

Of those internal requests, 78 were replay-page shells, not replay playthroughs. The link inventory also found 199 further replay links and 36 task links that were not part of the site-wide HTTP sweep; selected task pages were separately checked in depth. External editorial citations from every blog were not exhaustively checked. The external sweep covers the complete resource catalogue and core learning/participation destinations.

Site-wide coverage includes the homepage, benchmark pages, leaderboards/results, competition/current and archive routes, resources, guides, blog archive, about/history, partners, jobs, donation and linked participation destinations. Manual live-browser checks focused on the high-value task/result journeys, desktop and phone task layouts, filters, sorting, and ARC Explainer’s saved-attempt/analytics comparison.

  • Retracted as a current outage: the previously blank individual task page loaded its grids and table in this fresh check. Keep the old observation as intermittent only; do not ask the coding assistant to “fix” an assumed cause. The separate ARC3 task-index failure is reproduced.
  • Lab42: five of six listed destinations work. Only the editor is confirmed unavailable in this pass.
  • Hugging Face: the June update cutoff is observed, not proof of permanent discontinuation. Search included all three public ARC Prize HF datasets, the current benchmarking repository, recent model data links and Astra’s results/blog/client source.
  • Historical results: older reports and aggregate records remain. The issue is broken destinations and disconnected navigation, not wholesale deletion.
  • Existing credit: Resources already lists “ARC-AGI Puzzle Explorer” pointing to ARC Explainer’s analytics page. The useful request is clearer discovery of its individual-task tools and distinct learning resources.
  • Children/human play: existing listings include ARC Game, Brain Grid Game and a different Human ARC project. The gap is audience guidance and curation, not zero resources. No blanket judgment about the quality of every game is supported by this pass.
